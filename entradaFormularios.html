Formularios web: GET, POST y protección de contraseñas

Aprende cómo se envían los datos desde un formulario y qué medidas ayudan a protegerlos.

1. ¿Qué es un formulario web?

Los formularios web permiten recoger información introducida por los usuarios, como un nombre, una dirección de correo electrónico o una contraseña. Se utilizan, por ejemplo, en los formularios de inicio de sesión, los registros de usuarios y las búsquedas.

En HTML, la etiqueta <form> define el formulario. Dentro de ella podemos utilizar elementos como <input> para introducir datos y <button> para enviar la información.

Algunos atributos importantes son:

  • type: indica el tipo de dato que se introduce, como texto o contraseña.
  • name: identifica el dato cuando se envía el formulario.
  • action: indica la dirección a la que se envían los datos.
  • method: establece el método HTTP utilizado para enviar la información.

2. Diferencias entre GET y POST

GET y POST son dos métodos HTTP utilizados para realizar peticiones a un servidor. La principal diferencia está en cómo se transmiten los parámetros y en el uso que se suele dar a cada uno.

Método GET

GET se utiliza habitualmente para consultar información. Los parámetros suelen aparecer en la URL después del símbolo ? y se separan mediante &.

Por ejemplo:

https://ejemplo.com/buscar?tema=linux&pagina=1

Estos parámetros pueden quedar guardados en el historial del navegador, los registros del servidor o enlaces compartidos. Por eso no se deben incluir contraseñas en la URL.

Método POST

POST se utiliza habitualmente para enviar datos que el servidor debe procesar, por ejemplo, al registrar una cuenta o enviar un formulario. Los datos se incluyen en el cuerpo de la petición, en lugar de aparecer normalmente en la URL.

Sin embargo, POST no cifra los datos por sí mismo. Si se utiliza HTTP sin cifrar, la información puede ser interceptada durante la transmisión.

4. ¿POST protege las contraseñas?

No por sí solo. Utilizar POST evita que los parámetros se muestren normalmente en la URL, pero no impide que alguien pueda leerlos si la comunicación viaja sin cifrar.

Para proteger los datos durante su transmisión se utiliza HTTPS, que incorpora TLS para cifrar la comunicación entre el navegador y el servidor.

También es importante recordar que HTTPS no protege frente a todos los riesgos. Un servidor comprometido, una página fraudulenta o un sistema que almacene mal las contraseñas pueden seguir exponiendo información.

Algunas buenas prácticas son:

  • Utilizar HTTPS en las páginas que manejan información sensible.
  • No incluir contraseñas en las URL.
  • No almacenar contraseñas en texto plano.
  • Guardar las contraseñas mediante funciones de hash específicas para contraseñas, con sal y parámetros adecuados.
  • Validar los datos tanto en el navegador como en el servidor.

5. Comparativa de seguridad

Método y protocolo Características
GET con HTTP Los parámetros pueden aparecer en la URL y la comunicación no está cifrada.
POST con HTTP Los datos suelen ir en el cuerpo de la petición, pero la comunicación no está cifrada.
GET con HTTPS La comunicación está cifrada durante el transporte, aunque los parámetros pueden permanecer en el historial o en registros.
POST con HTTPS El cuerpo de la petición está protegido durante el transporte, pero siguen siendo necesarias otras medidas de seguridad.

En conclusión, GET y POST tienen usos distintos, pero ninguno sustituye al cifrado. La protección de la información depende también de cómo se procesa y almacena en el servidor.
